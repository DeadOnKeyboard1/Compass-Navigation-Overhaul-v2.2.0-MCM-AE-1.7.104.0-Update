## v4.2 follow-up: InfinityUI QuestItemList startup CTD

CrashLogger showed an access violation while InfinityUI was adding `HUDMovieBaseInstance.QuestItemList`, with CNO frames immediately above the InfinityUI message dispatch. The CNO InfinityUI listener still called `GFxValue::ToString()` on `DisplayObject` values in pre/post/abort replacement callbacks and in GFx debug logging. For Scaleform display objects this conversion is not a safe way to identify the ActionScript path and can enter the engine string-conversion path with invalid object/string state.

The listener now resolves the known Compass/QuestItemList path with `GFxMovieView::GetVariable()` and compares the resulting `GFxValue` object directly. All object/array debug logging was also changed to log the GFx type rather than calling `ToString()`. No marker, MCM, localization or packaging behavior was otherwise changed.


## v4.3 follow-up: fast-travel compass layout drift

Fast travel can cause InfinityUI to replace the Compass child while preserving the existing `CompassShoutMeterHolder`. The previous code reset its cached baseline whenever the Compass object rebound, then read the holder's current transform. Because that holder already contained the user's CNO MCM offset/scale, the next layout update treated the modified transform as the native baseline and applied the same MCM values again. Repeated HUD rebuilds therefore accumulated position/scale drift.

The native holder position and scale are now persisted as private ActionScript members on the holder itself. Rebinding or replacing only the Compass child reuses that same native baseline, while a genuinely new HUD holder captures a fresh baseline once. Layout application is also deferred until InfinityUI's `FinishLoadInstances` stage so intermediate patch state is never captured.
